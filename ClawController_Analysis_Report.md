## **2. Аналіз структури проекту**
### **2.1. Організація проекту**
Проект **ClawController** має чітку та логічну структуру, що відповідає сучасним стандартам розробки iOS-додатків:
- **`App/`**: Точка входу додатку (`ClawControllerApp.swift`).
- **`Features/`**: Модулі для різних функцій додатку (наприклад, `Chat/`, `Tasks/`, `Tools/`).
- **`Core/`**: Базові моделі та бізнес-логіка (наприклад, `ChatMessage.swift`, `ServerEvent.swift`).
- **`Networking/`**: Реалізація WebSocket-клієнта (`WebSocketManager.swift`).
- **`Config/`**: Конфігураційні файли (`.xcconfig`).

### **2.2. Сильні сторони**
✅ **Модульність**: Проект розділений на логічні модулі, що полегшує підтримку та розширення.
✅ **Використання сучасних технологій**: SwiftUI, Composable Architecture (TCA), `AsyncStream`.
✅ **Чітка структура**: Легко знайти потрібний файл або модуль.

### **2.3. Слабкі сторони**
⚠️ **Відсутність тестів**: У проекті не виявлено юніт-тестів або UI-тестів.
⚠️ **Жорстко закодовані налаштування**: URL WebSocket та інші параметри жорстко закодовані.
⚠️ **Недостатня документація**: Відсутні коментарі або README-файли з описом архітектури.

## **3. Аналіз коду**
### **3.1. Архітектура та дизайн-патерни**
- **Composable Architecture (TCA)**:
  - Використовується для управління станом додатку (`ChatReducer.swift`).
  - **Переваги**: Легкість тестування, передбачуваність стану.
  - **Недоліки**: Складність для новачків, велика кількість шаблонного коду.

- **WebSocketManager**:
  - Актор (`actor WebSocketManager`) для асинхронної роботи з WebSocket.
  - **Переваги**: Безпека потоків завдяки `actor`, підтримка heartbeat.
  - **Недоліки**: Відсутність автоматичного перепідключення.

- **Моделі даних**:
  - Використовуються `Codable` та `Equatable` (наприклад, `ChatMessage.swift`).
  - **Переваги**: Зручність роботи з JSON, підтримка SwiftUI (`Identifiable`).
  - **Недоліки**: Відсутність валідації даних.

### **3.2. Проблеми з продуктивністю**
1. **WebSocketManager**:
   - Використання `Timer` для heartbeat може призводити до зайвого навантаження на CPU.
   - **Рекомендація**: Замінити на `DispatchSourceTimer` або збільшити інтервал.

2. **ChatReducer**:
   - Масив `messages` не має обмеження на розмір, що може призводити до надмірного споживання пам'яті.
   - **Рекомендація**: Додати механізм обмеження розміру масиву.

3. **SwiftUI та TCA**:
   - Зайві перерендери UI через `Equatable`.
   - **Рекомендація**: Оптимізувати порівняння стану.

### **3.3. Витоки пам'яті**
1. **WebSocketManager**:
   - Не викликається `stopHeartbeat()` у `deinit`.
   - **Рекомендація**: Додати `deinit` для очищення ресурсів.

2. **AsyncStream**:
   - `eventContinuation` не завершується (`finish()`) при виклику `disconnect()`.
   - **Рекомендація**: Додати завершення `eventContinuation` у `disconnect()`.

3. **ChatReducer**:
   - Не очищається `currentSession` при завершенні сесії.
   - **Рекомендація**: Очищати `currentSession` у `runEnded`.

### **7.1. Основні помилки у логах**
#### **7.1.1. `invalid_tool_name`**
- **Опис**:
  У логах (`claw_trace.log`) виявлено помилку:
  ```
  error: invalid_tool_name: unsupported tool in --allowedTools: none
  ```
  - **Причина**: Некоректна назва інструменту (`none`) у параметрі `--allowedTools`.
  - **Модуль**: CLI-інтерфейс (не частина `ClawController`, але пов'язано з інфраструктурою проекту).
  - **Наслідки**: Неможливість запуску певних інструментів через CLI.

- **Рекомендації**:
  - Виправити конфігурацію CLI-інструментів, замінивши `none` на коректні назви (наприклад, `bash`, `read_file`).
  - Додати валідацію параметрів CLI перед запуском.

---

#### **7.1.2. `Broken pipe (os error 32)`**
- **Опис**:
  У логах (`debug.log`) виявлено помилку:
  ```
  error: Broken pipe (os error 32)
  ```
  - **Причина**: Розрив з'єднання WebSocket.
  - **Модуль**: `WebSocketManager.swift` (методи `connect()`, `receiveMessages()`).
  - **Наслідки**: Втрата з'єднання з сервером, що призводить до некоректної роботи додатку.

- **Рекомендації**:
  - Додати обробку помилки `Broken pipe` у методі `receiveMessages()`:
    ```swift
    catch {
        if !Task.isCancelled {
            connectionState = .error(.connectionFailed(error.localizedDescription))
            logger.error("Receive error: \(error.localizedDescription)")
            disconnect()
        }
        break
    }
    ```
  - Реалізувати автоматичне перепідключення при розриві з'єднання:
    ```swift
    private func handleConnectionLoss() {
        Task {
            try? await Task.sleep(nanoseconds: 5_000_000_000) // 5 секунд
            if case .error = connectionState {
                try? await connect()
            }
        }
    }
    ```
  - Викликати `handleConnectionLoss()` при виявленні помилки `Broken pipe`.

---

#### **7.1.3. `Failed to parse event`**
- **Опис**:
  У логах (`output.log`) виявлено попередження:
  ```
  logger.warning("Failed to parse event: \(line)")
  ```
  - **Причина**: Некоректний формат JSON або порожній рядок при десеріалізації подій WebSocket.
  - **Модуль**: `WebSocketManager.swift` (метод `parseAndEmitEvents(from:)`).
  - **Наслідки**: Втрата подій, що надходять через WebSocket.

- **Рекомендації**:
  - Додати детальне логування причини помилки:
    ```swift
    guard let data = line.data(using: .utf8),
          let event = try? JSONDecoder().decode(ServerEvent.self, from: data) else {
        logger.warning("Failed to parse event: \(line), error: \(String(describing: error))")
        continue
    }
    ```
  - Додати спробу десеріалізації з обробкою помилок:
    ```swift
    do {
        let event = try JSONDecoder().decode(ServerEvent.self, from: data)
        eventContinuation?.yield(event)
    } catch {
        logger.warning("Failed to parse event: \(line), error: \(error.localizedDescription)")
    }
    ```

---

#### **7.1.4. `Heartbeat failed`**
- **Опис**:
  У логах (`WebSocketManager.swift`) виявлено попередження:
  ```
  logger.warning("Heartbeat failed: \(error)")
  ```
  - **Причина**: Помилка відправки ping-повідомлення через WebSocket.
  - **Модуль**: `WebSocketManager.swift` (метод `startHeartbeat()`).
  - **Наслідки**: Нестабільне з'єднання з сервером, можлива втрата з'єднання.

- **Рекомендації**:
  - Додати повторні спроби відправки heartbeat:
    ```swift
    do {
        try await self.send(.ping)
    } catch {
        logger.warning("Heartbeat failed: \(error)")
        try? await Task.sleep(nanoseconds: 5_000_000_000) // 5 секунд
        if case .connected = self.connectionState {
            try? await self.send(.ping)
        }
    }
    ```
  - Додати перевірку стану з'єднання перед відправкою heartbeat:
    ```swift
    guard case .connected = self.connectionState else {
        logger.warning("Heartbeat skipped: not connected")
        return
    }
    ```

⚠️ **Неоптимальний heartbeat**:
   - Використання `Timer` для heartbeat може призводити до зайвого навантаження на CPU та батарею.

⚠️ **Відсутність обмеження на розмір масиву `messages`**:
   - У `ChatReducer.swift` масив `messages` не має обмеження на розмір, що може призводити до надмірного споживання пам'яті.

⚠️ **Зайві перерендери UI**:
   - Використання `Equatable` для стану (`ChatState`) може призводити до зайвих перерендерів UI.

---

#### **4. Витоки пам'яті**
⚠️ **Некоректне очищення ресурсів**:
   - У `WebSocketManager.swift` не викликається `stopHeartbeat()` у `deinit`, що може призводити до витоку пам'яті.

⚠️ **Незавершений `AsyncStream`**:
   - `eventContinuation` не завершується (`finish()`) при виклику `disconnect()`, що може призводити до витоку пам'яті.

⚠️ **Збереження непотрібних даних**:
   - У `ChatReducer.swift` не очищається `currentSession` при завершенні сесії, що може призводити до збереження непотрібних даних у пам'яті.

---

#### **5. Жорстко закодовані налаштування**
⚠️ **Жорстко закодовані URL**:
   - У `ChatEnvironment.swift` та `WebSocketManager.swift` використовуються жорстко закодовані URL (наприклад, `ws://localhost:8080/ws`), що ускладнює зміну середовища (дев/прод).

⚠️ **Жорстко закодовані налаштування логування**:
